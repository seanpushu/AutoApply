申请包把选定的岗位、联系方式、实际简历和认可的通用答案带到雇主页面。助手只有在你主动打开它时才能操作当前页面，没有后台扫描或模型调用。

一次性安装

  1. 下载投递助手 ZIP，解压到一个保留使用的文件夹。此电脑也已准备好输出目录中的 Summer27-投递助手 文件夹。
  2. 在 Chrome 地址栏输入 chrome://extensions；Edge 输入 edge://extensions。开启“开发者模式”，点击“加载已解压的扩展程序”。
  3. 选择包含 manifest.json 的投递助手文件夹。将“Summer 27 投递助手”固定到工具栏。

安装对象是 Chrome 或 Edge。Codex 内置浏览器不加载这份扩展。扩展尚未替你安装；安装不要求重启电脑，也不需要 API key。

每批申请这样做

  1. 在工作台 Application desk 选岗加入队列，查看匹配理由及资格冲突。公司规模由你标记；使用 Ashby、Greenhouse 或 Lever 不等于小公司。
  2. 选择实际 PDF / DOCX 简历，核对事实及联系方式，导出申请包。每包最多 20 个岗位、简历最多 3 MB；按 AIE / SDE / MLE 的材料版本分批。
  3. 在 Chrome / Edge 打开雇主申请页面，点击扩展，导入申请包。选定岗位并打开完整表单；如果扩展打开了新标签页，在该标签页再次点击扩展。
  4. 勾选预填与上传确认后点击预填。助手填入识别出的空白联系方式、完全相同的通用问题，选择该份简历；已填写的内容和附件会保留。选择附件可能立即上传到雇主服务器，因此这一步也需要你确认。
  5. 在原网页完成剩余问题、下拉选项、登录和验证码。工作授权、赞助、薪资、同意条款、敏感资料及求职动机需逐岗填写。
  6. 点击“读取表单”查看公司、岗位、全部识别字段、附件及原站提交目标。核对无误后勾选本次提交确认，点击“确认并提交这一份”。内容发生变化或超过两分钟，需重新读取并确认。
  7. 确认成功页面或邮件后，在助手填写回执说明并确认。导出回执文件，回到工作台导入，进度才更新为 Applied。点击提交本身仅记录为“待核实”。

当前覆盖与遇阻处理

支持上述三类平台官方域名中、能识别出唯一原生申请表和提交按钮的页面。自定义页面、嵌入表单、特殊上传组件或无法核验附件的页面可能只能预填一部分。遇到提示就在原网页继续完成，不会猜填或自动重试。

已有提交尝试的岗位会锁定助手重复提交。先核实雇主回执；确需重投时由你在原站处理。系统不会自动发送招聘者消息，也不会冒用雇主的申请 API 凭据。

本版通过模拟表单测试，未向真实公司提交测试申请。不同雇主的页面结构会变化，不能保证所有 Ashby / Greenhouse / Lever 表单均适用。

三天提醒与更新成本

此电脑已设置 Windows 本地提醒：每三天纽约时间上午 9:00，首次为 2026-09-10。原 Codex 定时任务已暂停。提醒本身不访问岗位来源、不调用模型、不消耗 GPT token；电脑须开机且用户已登录。

收到提醒后再决定是否更新。本机工作台的“确认更新”会在你确认后采集公开岗位，不调用模型。私密网页版可以复制更新指令，发到 Codex 后才开始研究及发布；该对话工作会消耗相应额度。不确认就不更新。同类产品和新技术也只在你要求更新功能时检查，不定时研究。

资料放在哪里

工作台个人记录保存在浏览器或本机备份；申请包包含完整简历及联系方式，导入后保存在当前 Chrome / Edge 的扩展数据库。它不会自动同步到其他设备或网站。只有你批准预填上传后，资料才会进入雇主页面。
